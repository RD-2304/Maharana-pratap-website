# Security and Privacy

## Protections in the site

- A Content Security Policy limits scripts, frames, media, network calls, and form targets to services the site uses.
- A `no-referrer` policy prevents page addresses and live-room invitation fragments from being sent to external services.
- Live-room invitations use a URL fragment (`#room=...`) rather than a query string, and attendee names are not saved in browser storage.
- Live-room codes generated by the site contain cryptographically random data; private-code creation stops if secure randomness is unavailable. Anyone who receives an invitation can still enter that room, so invitation links must be treated as private.
- Wikipedia links open without access to the source browser tab.
- The contact interface does not post form content to this website. It validates locally and opens the visitor's configured email app with an encoded draft.

## Deployment requirements

The published site URL indicates GitHub Pages hosting. In the GitHub Pages settings, enable **Enforce HTTPS** before inviting visitors to use a live room.

Some important controls require HTTP response headers and cannot be fully provided by HTML meta tags. If the site is later served through a host or proxy that permits custom headers, configure at least:

```text
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Content-Security-Policy: default-src 'self'; script-src 'self' https://meet.jit.si; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com data:; img-src 'self' data: blob:; media-src 'self'; connect-src 'self' https://en.wikipedia.org; frame-src https://meet.jit.si; object-src 'none'; base-uri 'self'; form-action 'self' https://www.google.com; frame-ancestors 'none'; upgrade-insecure-requests
Permissions-Policy: geolocation=(), payment=(), usb=(), camera=(self "https://meet.jit.si"), microphone=(self "https://meet.jit.si")
```

Only add `includeSubDomains` to HSTS if all subdomains are HTTPS-ready.

## Limits of the current live room

The page embeds a Jitsi meeting; Jitsi provides the real-time conferencing infrastructure. For private production meetings that require verified hosts, approved participants, moderation, audit logs, or service-level guarantees, use authenticated Jitsi/JaaS configuration or a self-hosted meeting deployment rather than a public anonymous room.

## Contact limits

The current contact feature opens an email draft; it does not provide server-side spam filtering, rate limiting, CAPTCHA, file scanning, or private database storage. Those protections require a contact backend or a trusted form service.
